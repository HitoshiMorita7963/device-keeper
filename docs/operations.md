# 運用手順

## 利用者の登録

1. 管理者でログインし、システム設定 → 利用者管理 → 新規登録 を開く
2. メールアドレス (ログイン ID)・表示名・権限・初期パスワード (12 文字以上) を入力する
   - 一般社員は、本人の社員情報を「社員」で選択する (自分の貸与端末を表示するため)
3. 初期パスワードは本人に安全な方法で伝え、初回ログイン後にヘッダーの鍵アイコンから変更してもらう

ログイン失敗が 5 回続くと 15 分間ロックされる。急ぎの場合は利用者編集画面の「パスワード再設定」でロックを解除できる。
退職者は社員詳細画面の「退職処理」を行うと、紐付いた利用者も自動で無効になる。

## バックアップ

```bash
npm run db:backup
```

`./backups/device_keeper_YYYYMMDD_HHMMSS.jsonl.gz` が作成される (`BACKUP_DIR` で変更可)。
新しい順に 30 世代を残し、それより古いものは自動で削除する (`BACKUP_KEEP` で変更可)。

### 定期実行の設定

1 日 1 回以上の実行を推奨する。バックアップファイルはサーバーとは別の場所 (ファイルサーバー・クラウドストレージ等) にも複製すること。

**Windows (タスク スケジューラ)**: 次の内容のバッチファイルを作成し、毎日実行するタスクとして登録する。

```bat
cd /d C:\apps\device-keeper
call npm run db:backup >> backups\backup.log 2>&1
```

**Linux (cron)**: `crontab -e` で次を追加する (毎日 2:00)。

```cron
0 2 * * * cd /opt/device-keeper && npm run db:backup >> backups/backup.log 2>&1
```

### バックアップの確認 (月 1 回程度を推奨)

```bash
npm run db:backup:verify
```

最新のバックアップを一時 DB (`<DB名>_restore_check`) に復元し、件数の一致とデータ整合性を確認してから一時 DB を削除する。
運用中の DB は変更しない。DB 利用者に `CREATE DATABASE` 権限が必要。

## 復元

障害やデータの誤操作から復旧する場合の手順。**現在の DB の内容はバックアップの内容で置き換わる。**

1. 利用者に作業を周知し、アプリを停止する
2. 念のため現在の状態をバックアップする: `npm run db:backup`
3. 復元するファイルを確認する: `npm run db:backup:list`
4. 復元する: `npm run db:restore -- backups/device_keeper_YYYYMMDD_HHMMSS.jsonl.gz --yes`
   - バックアップ作成時とアプリのバージョン (マイグレーション) が違う場合は中止される。その場合はバックアップ作成時のバージョンのアプリで `npm run db:deploy` を実行してから復元し、その後で新しいバージョンに更新する
5. 整合性を確認する: `npm run db:check` (エラー 0 件であること)
6. アプリを起動し、ログイン・主要画面の表示を確認する (ログイン中だった利用者は再ログインが必要)

## データ整合性チェック

システム設定 → データ整合性チェック、または `npm run db:check` で、端末状態・貸与履歴・修理記録・廃棄記録・拠点移動履歴の間に矛盾がないかを確認できる。
エラーは通常の操作では発生しない (DB を直接編集した場合などに発生する)。警告は運用上起こりうる状態 (退職者に未返却の端末がある等) のため、内容を確認して対応する。

## アプリの更新

1. `npm run db:backup`
2. 新しいバージョンのコードを配置し `npm ci`
3. `npm run db:deploy` (マイグレーション適用)
4. `npm run build` → アプリを再起動
5. `npm run db:check`
