## Phase 1 で実装したもの

- Next.js 16 + TypeScript + Tailwind CSS + shadcn/ui のプロジェクト
- Prisma スキーマ (全テーブル) と初回マイグレーション、初期データ投入 (`npm run db:seed`)
- 開発用 PostgreSQL 起動スクリプト (`npm run db:start`)
- ログイン / ログアウト、DB セッション、ログイン試行制限、監査ログ記録
- ロール別権限定義と画面・Server Action 用の権限チェック
- 共通レイアウト (ヘッダー・権限別サイドメニュー・スマートフォン用ドロワー)
- ダッシュボード (実データの集計)、一般社員向け「マイ端末」

## Phase 2 で実装したもの

- 部署管理・資産種別管理 (システム設定配下、管理者のみ)。資産種別ごとの採番形式 (プレフィックス・桁数) と次の番号を表示
- 拠点管理: 一覧 (検索・ページ送り・登録端末数)、詳細 (基本情報・所属端末・種別集計・移動履歴)、登録、編集
- 社員管理: 一覧 (氏名等・部署・拠点・在籍状態の組み合わせ検索、貸与端末数)、詳細 (貸与中端末・返却予定・過去の貸与履歴)、登録、編集
- 退職処理: 貸与中端末がある場合は警告し確認チェックを必須化。社員に紐づく利用者アカウントは無効化
- 業務ルール: 端末が残る拠点・在籍社員がいる部署は使用停止不可、通常の編集では退職に変更不可
- 共通部品: 入力検証スキーマ (画面・サーバー共通)、フォーム部品、検索バー、ページ送り

## Phase 3 で実装したもの

- 端末一覧: 資産管理番号・資産名称・シリアル番号・資産種別・メーカー・利用者・部署・拠点・状態・保証期限・返却期限超過を組み合わせて検索。ダッシュボードの集計カードから該当条件の一覧へ遷移
- 端末登録: 資産種別ごとの形式で自動採番 (カウンタ行ロックで同時登録でも重複しない、手入力済みの番号は飛ばす) または既存番号の手入力
- 端末編集: 拠点 (拠点間移動で変更) と状態 (状態変更・貸出・返却・廃棄で変更) は編集画面では変更しない。廃棄済み端末は編集不可
- 端末詳細: 基本情報・貸与情報・貸出履歴・拠点移動履歴・修理履歴・操作履歴 (変更前後の差分表示) のタブ
- 状態変更: 紛失・修理中への変更と復帰を理由付きで記録。貸出中は保管中に、未貸出は使用中にできない
- 削除: 履歴のない誤登録端末のみ論理削除 (資産管理番号は再利用しない)

## Phase 4 で実装したもの

- 貸出登録: 保管中の端末のみ選択可。貸与履歴登録・使用中への変更・現在利用者更新・操作履歴記録を 1 トランザクションで実行。確認画面あり
- 返却処理: 返却日・返却時状態・付属品確認・担当者を登録し、保管中へ戻して利用者を解除 (修理中の端末は修理中のまま)。確認画面あり
- 同時操作対策: 端末行を FOR UPDATE でロックしてから判定 (二重貸出・二重返却を防止)。DB の部分ユニークインデックスでも保証
- 貸出・返却管理画面: 貸出中・返却期限超過 (超過日数表示)・返却予定 (7日以内) の切り替え一覧
- 貸出履歴: 端末・利用者・状態・貸出日の範囲で検索
- 端末詳細・端末一覧・社員詳細から貸出/返却画面へ対象を引き継いで遷移
- 業務ルール: 退職者への貸出不可、貸出日・返却日の未来日不可、返却予定日・返却日は貸出日以降、担当者は管理者または IT 資産管理担当者

## Phase 5 で実装したもの

- 移動登録: 移動元は端末の現在拠点から自動設定。移動履歴登録・現在拠点更新・操作履歴記録を 1 トランザクションで実行 (端末行ロックで同時移動にも対応)。確認画面あり
- 業務ルール: 廃棄済み・紛失中の端末は移動不可、同一拠点・使用停止中の拠点への移動不可、移動日は未来日不可かつ前回の移動日以降、移動理由は必須。貸出中の端末は利用者を保ったまま移動できる
- 移動履歴: 端末・移動元・移動先・移動日の範囲で検索
- 拠点別端末一覧: 拠点一覧に拠点 × 資産種別の端末数集計を追加 (数値から該当端末一覧へ遷移)。拠点詳細の所属端末一覧から移動登録へ遷移
- 端末詳細・端末一覧から移動登録へ対象を引き継いで遷移

## Phase 6 で実装したもの

- CSV インポート (端末・社員・拠点): ファイル選択 → 項目の自動対応付け (変更可) → プレビュー (行ごとに 登録/更新/スキップ/エラー と理由を表示) → 確認画面 → 登録 → 結果表示
  - Excel の Shift_JIS と UTF-8 (BOM 有無) を自動判別。最大 2,000 行・2MB
  - 既存データの扱いを明示的に選択: 「スキップ (新規のみ)」または「更新 (値のある項目のみ上書き、空欄は既存値を維持)」。変更がない行はスキップ
  - エラーが 1 件でもあれば登録しない。登録は全行を 1 トランザクションで実行し、実行時にも判定をやり直す
  - 端末: 資産管理番号が空欄なら自動採番、種別・拠点はコード/名称のどちらでも指定可、利用者社員番号を指定すると貸出中として登録。拠点・状態・利用者は CSV で更新しない
  - 権限: CSV インポート権限に加え、対象データの編集権限が必要 (IT資産管理担当者は端末のみ)
  - テンプレート (見出し行のみの CSV) をダウンロード可能
- CSV エクスポート: 端末一覧・拠点別端末一覧・社員一覧・貸出履歴。一覧画面の検索条件で絞り込んで出力。UTF-8 BOM 付き (Excel で文字化けしない)、数式インジェクション対策、出力操作を操作履歴に記録
  - 端末一覧の CSV はインポートと同じ見出しのため、編集してそのまま再取り込みできる

## Phase 7 で実装したもの

- 修理登録: 端末状態を修理中にし、受付前の状態を記録。確認画面あり。対応中の修理は 1 端末 1 件まで (DB の部分ユニークインデックスでも保証)。廃棄済み・紛失の端末は登録不可
- 修理記録の更新: 業者・費用・状況を更新。完了 (修理完了日必須)・取消にすると端末状態を戻す (貸出中なら使用中、それ以外は保管中)。完了・取消後は状況を変更不可 (費用等の訂正のみ)
- 修理履歴: 対応中 (既定)・状況・業者・受付日で検索し、修理費用を合計表示
- 廃棄処理 (管理者のみ): 廃棄日・理由・方法・業者・データ消去の確認 (消去済み/不要を明示選択) を記録し、端末を廃棄済みにする。取り消し不可の操作のため確認チェック付きの確認画面。貸出中・修理対応中の端末は不可、紛失端末は除却として廃棄可
- 廃棄履歴: 端末・廃棄日で検索。廃棄済み端末の貸与・移動・修理の履歴はすべて保持
- 端末詳細から修理登録・修理記録・廃棄へ遷移。修理対応中は手動の状態変更を紛失のみに制限
- 共通: 端末詳細・社員詳細から開いた登録画面は、登録後に最終的に選ばれた端末 (社員) の詳細へ戻る

## Phase 8 で実装したもの

- 操作履歴画面: 期間・操作者・操作・対象・対象 ID で検索。変更前後の差分を日本語の項目名・値で表示。閲覧のみ (変更・削除の手段なし)
- 利用者管理 (管理者): 登録・権限変更・無効化・パスワード再設定 (ロック解除)。自分自身の権限変更・無効化、最後の管理者の降格は不可。権限変更等で該当利用者のセッションを無効化
- パスワード変更 (全利用者): 現在のパスワード確認、変更後は他の端末のセッションを無効化
- データ整合性チェック: 画面 (システム設定) と `npm run db:check`
- バックアップ・復元: `npm run db:backup` / `db:backup:verify` / `db:restore`。手順書 [operations.md](operations.md)
- テスト
  - 権限テスト: サーバー側の権限チェック (各 Phase の結合テスト) と、本番ビルドに対する全 37 画面 × 3 権限 + 未ログインの E2E テスト (`npm run test:e2e`)
  - データ整合性テスト: 貸出・返却・移動・修理・状態変更・廃棄・退職を固定シードの乱数で 300 回実行した後、矛盾がないことを確認
  - CSV テスト: 取り込み・出力・往復 (出力→取り込みで変更なし)・Shift_JIS 判定
  - 画面表示テスト: E2E で全画面が正常に表示されること (サーバーエラーなし)、一般社員に他人の端末が表示されないこと、セキュリティヘッダー
  - バックアップ・復元確認: 復元後に全テーブルの内容が完全一致すること、採番の続き、確認なしで復元しないこと

## 既知の制限・今後の検討事項

- 認証はメールアドレス + パスワード。Microsoft 365 を利用している場合は Entra ID による SSO への切り替えを検討する (`users.external_auth_id` を用意済み。`src/lib/auth/login.ts` を差し替える)
- 一般社員からの貸出・返却申請 (将来機能) は未実装
- 操作履歴で資産種別・部署などは ID で表示される項目がある (名称を記録している拠点・利用者は名称で表示)
- MDM による端末制御・遠隔ロック・遠隔初期化は対象外 (指示書どおり)
